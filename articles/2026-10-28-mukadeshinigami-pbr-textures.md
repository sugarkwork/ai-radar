# 1枚の参照画像からプロ級 PBR テクスチャを作る（Blender + Claude）

## テーマ

実在するテクスチャ写真を1枚の参照にして、albedo / height / normal / roughness / AO のマップ一式を Blender と Claude（Opus 5.5）で作るワークフロー。プロシージャルノイズでは岩石の「割れ方」のような実在感が出ない、という前提から出発している。

## 著者の主張

- 必要なマップは5種。1マップにつき2〜4候補を生成し、後で選抜する。
- 選抜基準は「焼き込まれた光の少なさ」。albedo は影のない平坦なもの、normal は平均が (128,128,255) のもの、roughness は影を含まないもの。
- 最重要工程は位置合わせ。全マップを albedo に光学フローで合わせ、明度ではなくエッジ構造で比較する（normal は陰影画像に変換してから比較）。
- 実測で3〜4px ずれていたマップが 0.1〜0.3px に収束した（0.5px 未満は不可視）。
- height から normal を作り直すことで、height と normal の不一致を構造的に消せる。
- 仕上げ値の例：rock roughness を 0.62〜1.0 に圧縮、specular 0.2、normal strength 1.4、AO 55%、変位 0.045。
- 球体への貼り付けは UV 球でもトライプラナーでもなく、半球2枚＋赤道クロスフェードで解決する。
- 8K は 2752×1536 からのアップスケールで「真の8Kではない」と著者自身が明記。Real-ESRGAN の細部は plausible（もっともらしいが発明）と書いている。
- 限界も明記：1参照ではタイル化できない、AI アップスケールは発明、実変位はゲームには重い、GLB ベイクで苔の光沢と subsurface は失われる。

## 裏取り・注意点

- **コードが取得できていない**。X の記事取得ではコードブロック（プロンプト雛形、位置合わせスクリプト、Blender のマテリアルスクリプト）が本文に含まれず欠落している。手順の考え方は追えるが、そのまま再現はできない。
- 数値（0.1〜0.3px、2752×1536、8192×4572 など）は著者の実測記録で、**独立検証はしていない**。
- 「8K だが真の8Kではない」という但し書きは著者本人によるもので、記事の主張の中では最も重要な注意点。
- ワークフロー自体（光学フローでの位置合わせ、height から normal の再生成）は一般的な技術で、主張の骨格に無理はない。ただし効果量は環境依存。

# Claude Code サブエージェントを1ファイルで定義し、報告を短く縛る

## テーマ

- Claude Code のカスタムサブエージェントを .claude/agents/ の Markdown 1枚で定義し、親セッションには短い報告だけ返させる使い方。2026-10-22 の日本語投稿が、英語圏の投稿（現在は削除済み）の内容として紹介したもの。
- 主題は配布物ではなく技法。定義ファイルの書式、サブエージェントが別コンテキストで動く仕組み、利用上限への計上は Anthropic の公式ドキュメントで確認できる。

## 著者の主張

- （紹介元の要約）3体のサブエージェントに作業を任せ、合計32万7千トークン分を処理させたが、親の会話に戻ったのは短い報告3本だけ。ファイルの読み込みもログも行き止まりも親には入らない。
- 定義例「test-fixer」: description は「テストを回して落ちたら直す。コードを変えたあとに使う」、tools は Read・Edit・Bash、本文は「テストを回して落ちたものを直す。返事は5行まで：何が壊れたか、何を変えたか、まだ何が落ちてるか」に相当する内容（日本語の紹介からの再構成で、原文の語句そのものではない）。
- 報告の上限を先に決めておく発想は、他のサブエージェントにもそのまま持ち込めると主張している。
- 「毎回読ませる場所」と「必要なときだけ開く場所」を分けると会話が埋まりにくい、という整理も添えている。

## 裏取り・注意点

- 公式で確認できた: サブエージェントは Markdown + YAML frontmatter のファイル。プロジェクト単位は .claude/agents/、全プロジェクト共通は ~/.claude/agents/。必須は name と description で、tools に並べたものだけを使わせられる。
- 公式で確認できた: 各サブエージェントは独自のコンテキストウィンドウを持ち、本体には summary だけを返す。ただしそのリクエストは本体と同じ利用上限に計上される（親が小さく保てることと、タダになることは別）。
- 確認できない: 3体・32万7千トークン・報告3本という実測値。元ポストは HTTP 404 で、数字は投稿者の主張として扱い、測定値としては扱わない。
- 未検証: 「5行」の縛りが実際にどれだけ出力を減らすか。公式ドキュメントに報告長の制約はなく、効果は指示の書き方とタスク次第。
- 注意: description は常時コンテキストを消費する。全サブエージェントの description 合計が15,000トークンを超えると起動時に警告が出るので、詳細は本文（システムプロンプト）側に移す。
- 注意: この候補に添付されていた画像 https://pbs.twimg.com/media/HWWvkhaa4AAPVqD.jpg は別トピック（stageshow スキル）の紹介画像で、サブエージェント定義の画面ではない。一次証拠にしない。

# Ponytail

## 出来ること

- コードを書く前に「それは既にあるか」をエージェントに確認させるスキル。いきなり実装に入らず、次の順で問い、当てはまった所で止まる。
  1. リポジトリに既にある部品で済まないか
  2. 標準ライブラリ・ブラウザ・OS がすでに持っていないか
  3. 入っている依存で足りないか、1行で済まないか
  4. どれも駄目なら、動く最小の版と（ロジックがあれば）小さなテスト1本
- 削ってはいけないものを明示している：入力検証・エラー処理・セキュリティ・アクセシビリティ。
- `/ponytail-review` … 変更が触るコードを読んで、バグ・セキュリティ・実負荷・テスト欠落・速度・削れる箇所を点検する。指摘ごとに「何をしているか／何が壊れるか／どう直すか／直さないとどうなるか」を書く。
- `/ponytail-audit` … 同じ検査をリポジトリ全体に対して行う。先にコードを地図化（入口・データの流れ・想定負荷）してから、直す順番を付けて返す。
- Claude Code のプラグインとしても、Codex 向けコマンドとしても使える。

## 目的・背景

「長いポニーテールに丸眼鏡、バージョン管理より前からいる年上のエンジニア」という比喩で、**書かない技術**をエージェントに教えるスキル。作者の主張は「ルールは『トークンを最小化する』ではなく、『タスクに必要な分だけ書き、検証・エラー処理・セキュリティ・アクセシビリティは削らない』」。結果としてコードが短くなるのは副作用だと明記している。2026-06 作成、現在 ★18万超。

## 依存関係

- コーディングエージェント（Claude Code / Codex。プラグイン機構を使う）
- Node.js（プラグイン導入に npx を使う）
- 追加のランタイム依存なし（スキルは Markdown とプロンプト）

## 実行条件

- OS 不問。GPU 不要。
- ネット接続（マーケットプレイス取得）。
- 効果は「既存コードベースがある」ほど出る。空のリポジトリでは「既にあるか」の問いが空振りする。
